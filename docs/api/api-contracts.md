# PORTOS AI — API Contracts & Specifications

**Document ID:** `API-SPEC-001`  
**Version:** 1.0  
**API Prefix:** `/api/v1`  
**Protocol:** RESTful JSON over HTTP  
**Timezone Standard:** All storage and payload timestamps are UTC (ISO 8601). Display localized to `Asia/Dhaka (UTC+6)`.

---

## 1. Global Conventions

### 1.1 Headers
- `Accept: application/json`
- `Content-Type: application/json`
- `X-Request-ID`: Client-supplied or server-generated correlation ID returned in every response header and error payload.

### 1.2 Data Status Taxonomy
Every record carries an explicit `data_status` enum:
- `SIMULATED`: Artificially generated via seed engine or simulator.
- `OBSERVED`: Ingested from verified historical records or official bulletins.
- `FORECAST`: Generated by machine learning inference or predictive forecasters.
- `DERIVED`: Computed mathematically from activity and factor multipliers.
- `UNAVAILABLE`: Unmonitored, offline, or disconnected data feeds.

### 1.3 Physical Units
- Length & Draft: **metres (m)**
- Speed: **knots (kn)**
- Distance: **nautical miles (NM)**
- Cargo: **Twenty-Foot Equivalent Units (TEU)**
- Equipment Mass: **tonnes (t)**
- Power: **kilowatt-hours (kWh)**
- Emissions: **kilograms CO2 equivalent (kg CO2e)**

---

## 2. Standardized Error Response Envelope

All error responses (400, 404, 422, 500) return a uniform schema:
```json
{
  "error": "HTTP 404",
  "detail": "Vessel call with ID 'call_vsl_99' not found.",
  "request_id": "8f12a4b9-1234-5678-abcd-ef0123456789"
}
```

- `GET /health` — Service health check.
  - **Response 200:**
    ```json
    {
      "status": "ok",
      "service": "portos-backend",
    ```

### 3.3 Berths & Allocation
- `GET /api/v1/berths` — List berths (Query params: `terminal_id`, `status`).

### 3.5 Equipment Fleet & Telemetry
