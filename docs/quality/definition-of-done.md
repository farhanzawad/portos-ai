# Definition of Done (DoD) & Acceptance Standards — PORTOS AI

**Document ID:** `QUAL-DOD-001`  
**Version:** 1.0  
**Effective Date:** November 2026  
**Scope:** All milestone deliverables, pull requests, and automated agent coding tasks in PORTOS AI.

---

## 1. Prime Acceptance Standard

A feature or milestone is **never** considered complete simply because it renders visually or "looks correct."  
A feature is complete only when all criteria in this document are verified with fresh, executable evidence.

---

## 2. Core Functional Acceptance Checklist

Every user-facing feature and API endpoint must satisfy these eight baseline rules:

- [ ] **1. Functional User Interaction:** The feature responds correctly to user actions (clicks, form submissions, filters, sorting, drag/pan/zoom). No dead links, fake buttons, or dummy interactive elements.
- [ ] **2. Live API / Fixture Binding:** Components receive data from the documented FastAPI backend (`/api/v1/...`) or a designated, typed static fixture. No hardcoded mock values embedded in presentation components.
- [ ] **3. Complete State Coverage:** Every view and component cleanly implements all four lifecycle states:
  - **Loading State:** Skeleton loaders or subtle indicators (no layout shift).
  - **Empty State:** Helpful descriptive message and suggested user action.
  - **Error State:** Human-readable explanation with retry or fallback option (no unhandled exceptions).
  - **Unavailable State:** Explicit indication when a sensor, feed, or external model is unconfigured or offline.
- [ ] **4. Robust Defensive Handling:** Gracefully handles invalid, null, malformed, or extreme data boundaries without application crashes or white-screen errors.
- [ ] **5. Verification & Test Coverage:** Unit, integration, or browser tests verify core logic and catch regressions.
- [ ] **6. Visible Provenance & Data Status:** Displays explicit status badges (`SIMULATED`, `OBSERVED`, `FORECAST`, `DERIVED`, `UNAVAILABLE`) and provenance links where data is presented.
- [ ] **7. Truthful Capabilities:** The interface makes no claims about unbuilt features, fictitious live port connections, or unverified performance statistics.
- [ ] **8. Design System Alignment:** Follows **Minimal Industrial Futurism** styling: palette tokens, 8pt spacing grid, tabular numbers, Lucide icons, and restrained transitions (160–240 ms).

## 3. Engineering & Technical Quality Standards

### Frontend Quality
- **TypeScript Strictness:** Zero TypeScript errors (`tsc --noEmit`). No `any` type escapes unless strictly isolated with an explanatory comment.
- **Linting & Formatting:** ESLint passes with zero warnings or errors.
- **Console Hygiene:** Zero unhandled runtime exceptions, React hydration errors, or missing key warnings in browser developer tools.
- **Performance & 3D Hygiene:** Three.js canvases use instancing for repeated geometry; dynamic loading prevents SSR errors; 2D fallback engages if WebGL fails.
- **Accessibility:** Meets WCAG 2.1 AA contrast standards; supports keyboard navigation (`Tab` / `Enter` / `Esc`); respects `prefers-reduced-motion`.

### Backend Quality
- **Type Checking & Validation:** All API inputs and outputs strictly validated using Pydantic v2 schemas.
- **Architecture Separation:** Domain logic partitioned into routers, services, repositories, schemas, and analytics engines (no monolithic routes file).
- **Test Execution:** `pytest` passes cleanly across unit tests, domain models, and API endpoints.
- **Database Migrations:** Alembic migrations apply cleanly from a zero state; seed scripts are completely idempotent (running twice produces identical database state without duplicates).
- **No Hallucinated Math:** Simulation and optimization numbers are strictly generated by SimPy, OR-Tools, or scikit-learn.

---

## 4. Security & Privacy Guardrails

- [ ] **Credential Protection:** Secrets, API keys (`GEMINI_API_KEY`), and database credentials reside exclusively in server-side environment variables. No credentials exist in client bundles, `.env` files in git, or logs.
- [ ] **Input Sanitization:** Port Data Bridge sanitizes uploaded files against path traversal (`../`), limits file size (max 10MB), and strips spreadsheet formula injection triggers (`=`, `+`, `-`, `@`).
- [ ] **Prompt Injection Defense:** Imported documents are treated as untrusted data strings, never as direct instructions to the Gemini Copilot.
- [ ] **Privacy Preservation:** No personally identifiable information (PII) or confidential cargo pricing contracts are stored or processed.

---

## 5. Milestone Completion Protocol

Before declaring any milestone (Prompt 01–17) finished:
1. **Run Full Verification Suite:**
   - Frontend: `npm run lint && npm run typecheck && npm run build` (or equivalent).
   - Backend: `pytest` and linter checks (`ruff check .`).
2. **Inspect Changed Files:** Ensure no unintended edits or temporary debugging logs were left behind.
3. **Update Roadmap:** Mark the milestone as complete in `docs/roadmap.md` with the verified date and command results.
4. **Report Concrete Evidence:** Include command outputs, test counts, and exit codes in the summary to the user.
