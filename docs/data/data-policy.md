# Data Governance, Classification & Provenance Policy

**Document ID:** `DATA-POL-001`  
**Version:** 1.0  
**Effective Date:** November 2026  
**Scope:** All datasets, APIs, models, seed files, and UI presentations in PORTOS AI.

---

## 1. Core Principles of Operational Truthfulness

PORTOS AI maintains strict data integrity and transparency:
1. **No Data Fabrication:** Under no circumstances should simulated, generated, or hypothetical data be presented as live, observed real-world data from the Chattogram Port Authority (CPA) or any live maritime entity.
2. **Persistent Demonstration Context:** Whenever the system operates on synthetic or demo seed records, a persistent `DEMO ENVIRONMENT` banner must remain visible, and individual records must display their data status.
3. **No Unsubstantiated Impact Claims:** Simulated waiting time reductions or emissions savings produced by OR-Tools or SimPy represent model outputs within a closed simulation. They must never be described as "proven savings achieved at Chattogram Port."

---

## 2. Standardized 5-Tier Data Status Classification

Every operational record, table row, KPI card, and visual entity in PORTOS AI must carry one of the following five statuses:

| Status Tag | Definition & Criteria | Visual Badge Color | Example Entity |
| :--- | :--- | :--- | :--- |
| **`SIMULATED`** | Generated artificially via synthetic data generators, deterministic seed scripts, or the SimPy discrete-event simulator. | Muted Slate / Grey | Demo vessel `MV-001` current speed and position. |
| **`OBSERVED`** | Ingested directly from verified historical public reports, authorized documents, or official statistical tables without modification. | Teal / Green | Historical monthly container throughput from a published CPA report. |
| **`FORECAST`** | Generated by machine learning or statistical predictive models over a forward-looking time horizon. | Blue / Indigo | Predicted arrival delay: `+3.4 hours` (Model: `eta_gb_v1.0`). |
| **`DERIVED`** | Calculated deterministically from known formulas, aggregations, or factor tables. | Amber / Orange | Estimated auxiliary fuel consumption = `waiting_hours × fuel_burn_rate`. |
| **`UNAVAILABLE`** | Data feed is offline, sensor is unconfigured, or data cannot be observed. | Dashed Red / Warning | Live AIS tracking when no external provider key is active. |

## 3. Mandatory Provenance Tracking Schema

All persistent operational records in the database and API payloads must include the following provenance metadata fields where applicable:

```json
{
  "id": "vcall_9f8c2b1e",
  "data_status": "SIMULATED",
  "source_name": "PORTOS Deterministic Seed Generator",
  "source_url": null,
  "source_document_id": "seed_scenario_baseline_v1",
  "observed_at": "2026-11-02T16:00:00Z",
  "ingested_at": "2026-11-02T16:00:00Z",
  "methodology_note": "Generated for illustrative 12-vessel terminal demonstration.",
  "model_name": null,
  "model_version": null,
  "created_at": "2026-11-02T16:00:00Z",
  "updated_at": "2026-11-02T16:00:00Z"
}
```

For predictive inferences (`FORECAST`), the payload must also specify:
- `model_name`: Formal identifier (e.g., `vessel_delay_classifier`).
- `model_version`: Semantic version tag (e.g., `1.0.0`).
- `prediction_confidence`: Uncertainty or prediction interval where supported.
- `evaluation_caveat`: `"Synthetic test pipeline validation only."`

## 4. Port Data Bridge Ingestion Standards

The Port Data Bridge allows operators to import operational data via CSV, XLSX, and text-based PDF:
1. **Untrusted Data Boundary:** All uploaded files are treated as untrusted user inputs.
   - Files are parsed in memory or isolated temporary directories.
   - Filenames are sanitized to prevent directory traversal attacks (`../`).
   - Maximum upload file size is capped (e.g., 10 MB).
   - Spreadsheet cells are sanitized against formula injection (preventing leading `=`, `+`, `-`, `@`).
2. **Text-Only PDF Parsing:** PDF extraction is restricted to text streams via `pypdf`. Scanned image PDFs without extractable text must trigger an explicit message: `"No extractable text found. Scanned PDF processing requires manual entry or an OCR extension."`
3. **Human-in-the-Loop Review:** Uploaded datasets are staged in a temporary preview table. The operator must inspect identified columns, units, and sample rows before committing data to operational tables.

## 5. Units & Timezone Standardization

To ensure zero ambiguity in operational and environmental reporting:

### Timezones
- **Database Storage & API Transfer:** Always UTC (ISO 8601 format, e.g., `2026-11-02T16:00:00Z`).
- **User Interface Display:** Localized to Bangladesh Standard Time (`Asia/Dhaka`, UTC+6) with explicit labels: `BST` or `(UTC+6)`.

### Measurement Units
- **Vessel Dimensions:** Length Overall (LOA) in **metres (m)**, Maximum Draft in **metres (m)**.
- **Cargo Quantities:** Twenty-Foot Equivalent Units (**TEU**), Gross Weight in **tonnes (t)**.
- **Speeds & Distances:** Speed in **knots (kn)**, Nautical Distances in **nautical miles (NM)**.
- **Equipment & Fuel:** Electrical consumption in **kilowatt-hours (kWh)**, Fuel in **metric tonnes (MT)**.
- **Emissions:** Carbon equivalent in **kilograms of CO2 equivalent (kg CO2e)**.

---

## 6. Privacy & Sensitive Information Safeguards

PORTOS AI focuses exclusively on macro operational coordination:
- **No Personally Identifiable Information (PII):** Consignee names, addresses, passport numbers, and crew identities are strictly excluded from all schemas.
- **No Commercial Tariffs:** Specific cargo freight rates, commercial bills of lading, and proprietary shipping contracts are omitted.
- **Synthetic Entity Masking:** Illustrative demo vessels use synthetic identifiers (e.g., `DEMO-VESSEL-01` or fictionalized regional names such as `MV Karnaphuli Feeder`).
